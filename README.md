# Seedance 场景分镜导演

本 Skill 将完整中文剧本整理成标准稿，筛选并设计可复用人物、场景和主要道具，输出 Gpt-image-2 图片提示词，按人数拆分剧本并按指定范围生成 Seedance 2.5 分镜提示词。通过用户选择的小云雀CLI操作画布，不自动生成图片或视频。当前版本为 **v0.69**，更新日期 **2026-11-12**，以 `VERSION` 为准。

v0.69按用户约定将资产与分镜统一为默认20个一批，共用同一个默认值，保持依赖顺序和既有恢复机制。20是本地逻辑分组，不是服务端上限或已证明最优值；一组可按命令类型拆成多次提交及回读。

v0.68固定适配小云雀CLI 1.0.57，采用公开命令批量写入、按ID回读、后台自动退避和原ID安全补做。分镜引用以已映射节点ID为准，保留用户上传图片后的名称。

v0.66 在新分镜的自动校验中核对纯黑画面的剧本依据，并累计跨镜头、跨单元的连续黑场时长。只有剧本在该处明确要求切黑或全黑才可使用，连续超过3秒即退回。

配镜和估时前先判断完整事件中哪些动作必须看清、哪些过程可以省略、哪些声画可以同期。相容的动作与台词一律并行，基础镜长为1～7秒；审阅完成后、最终输出前，基础总长4秒的单元完整保留，其余单元的4～7秒镜头各减1秒。每镜明确首帧人物位置、朝向、视线与对话对象，并与起始机位对应；自然中间空间变化交给Seedance 2.5推演，保留原有动作和运镜要求。独立主审在既有整场阅读中核对节奏、首帧关系、动作运镜矛盾及镜间承接，[分镜节奏回归样例](references/storyboard-pacing-evals.md)供不同题材的盲测使用。

声音与交付规则保留整镜机械容量快速排错，增加实际发声窗口及数字、英文、缩写读法检查，支持有来源依据的不同声源叠话；区分剧情必要文字与额外字幕。统一全剧标准化、资产与正式分段的完成条件，分段用于动画协作及逐段分镜制作；本地制作与云端同步分别推进，并统一自动同步授权。OS内心独白约定、运镜硬约束、镜长与光照要求保持，26～30秒优先仅用于分镜单元拆分与组合。

已绑定分镜项目支持导出交接包、导入新目录、路径重定位及检查点续接；正常正式项目走默认路径，已审本地交付与同源早期项目按需要兼容，统一入口见[项目迁移](references/project-portability.md)。

角色、场景和道具生图提示词按节点类型写入并回读，三条资产初始化入口共用适配，保留独立描述、主图及已有生成配置。派生角色图片通过基础角色与相关道具引用表达允许差异，编译和画布绑定分别核验依赖；节点初始化完成与参考图片输入就绪分开报告。上传素材source ID、Pippit ID与云媒体ID分别保存。支持三种官方画布链接，按域名与路径保留空间线索，候选空间经只读核验后保存，后续命令及跨进程恢复自动沿用；旧任务不自动迁移或解除暂停。图片派生规则归[图片设计](references/asset-image-design.md)，画布契约、流程和队列分别归[画布接口](references/canvas.md)、[工作流](references/canvas-workflow.md)和[后台队列](references/canvas-jobs.md)。

共同事件按实际参与者和操作对象组织；动作与对白同期估时，日常过程选取必要相位，短暂手势按作用条件结束，持续操控与接触关系按实际条件承接。分镜先估计自然执行负荷，确定1～7秒基础整数镜长并优先组合连续内容，完成独立审阅及修订后再执行一次最终减秒；声音、动作、运镜共同考虑，必要慢速和叙事停顿按来源保留，不因组合目标拖慢执行，也不因节奏变紧将短节拍各自拆成单元。估时参数、组合目标及摄影约束只在[创作规则总集](references/storyboard-rules.md)维护，新稿不自动输出普通语速标签或倍速指令。画布任务记录未报告事件，桌面提示与聊天完成反馈分别处理，后续入口依当前用户意图衔接。标准化、资产审阅与美术设计继续按各阶段权威规则执行，职责导航见[规则归属](references/rule-domains.md#当前规则归属)。

分镜规则按叙事视角、信息组织、运镜时机与切点维护。焦点表演围绕实际刺激、对象和变化落点展开，声音按既有语义选择字头、重音、句势及收音，平淡或克制不自动弱化为迟缓与无力。机位和构图可强化已成立的对抗与主导关系，但不将狠话机械映射为仰拍。情绪进程、表里关系、哭戏阶段和部位词库均服从来源与可见条件，面部、身体与声音保持相容；动作过程、拟音及跨镜状态分别依对应章节处理。短节拍和一次独立整场阅读负责实际取舍，局部修改复看真实影响。按场只读上下文由storyboard_context提供，预览完成后自动绑定实际产物记录成功，storyboard_metrics从有效事件派生计量并保留明确撤销记录；沿用文字命令入口，不增加逐镜表单或审核轮次。镜长依据未完成的观看任务确定；局部慢动作的起止、跨镜运动相位和当前损坏状态依创作规则处理，作者同次书写核对与独立整场审阅共同执行。用户提供实际视频时另核实对应画面，文字审阅不代替视频效果验收。具体规则和接口分别维护于下列三份分镜资料。

新分镜采用 **scene-text-v1 文字母稿**：范围简报一次，当前场短节拍，由作者逐镜直接写完整提示词，绝对禁止脚本生成或改写创作内容；新绑定项目同时启用 `shot-by-shot-v1` 作者闸门，每镜保留来源、观看决定和自然时长依据，必要状态及关键节奏直接落实到正文，侧车不进入最终TXT模板。作者连续逐镜写作并按疑点执行增量诊断，每场由一位独立主审完整阅读一次，集中修订后只复看改动与受影响连接。场末只记后续需要的事实，范围末只核覆盖和场次连接。脚本负责原样保存、校验作者已定的原话/基础时轴/引用，以及编号、已审稿的固定时长转换、导出和实际事件计时；[创作与工具边界](references/execution-contract.md#分镜创作与工具边界)统一维护允许范围。

新稿只需[分镜工作流](references/storyboard-workflow.md)、[创作规则总集](references/storyboard-rules.md)和[文本母稿格式](references/storyboard-text-format.md)三份资料；命令另由[后台接口](references/runtime.md)索引。历史回执与旧接口边界见[历史回执兼容](references/runtime.md#历史回执兼容)。旧参考文档已退出安装包，仍被调用的兼容实现保留；安装不会迁移真实项目、资产或Canvas状态。

标准化与资产阶段按职责读取四份资料：[主流程](references/asset-workflow.md)、[标准化及复核观察协议](modules/screenplay-standardizer/INSTRUCTIONS.md)、[资产台账与审阅决定](modules/screenplay-standardizer/references/asset-ledger.md)、[图片设计与共享分组](references/asset-image-design.md)。原补充分散页的有效规则已归并，旧资产入口和设计分组兼容页已移除，活动引用直接指向对应权威文件。

## 使用

1. 发送完整剧本后先选择并保存风格，再输入并保存项目固定抬头，最后独立选择并保存视频比例；已有项目设置不重复问。固定抬头保存为项目`video-header.txt`，资产节点始终16:9；视频比例用于分镜标题、新建视频节点和新分镜单元的画幅配置，16:9沿用现有横屏规则，9:16按[竖屏9:16配置](references/storyboard-rules.md#竖屏9:16配置)执行。
2. 完成标准化、来源复核、资产筛选与美术设计，交付标准剧本TXT、最终资产台账JSON、分类图片提示词TXT。原人物行的编号、形象描述及组合分别建立形象资产，台词逐字保留；正文换装与佩戴按实际完成位置切换，普通派生以首次形象保持面部身份，佩戴引用当时适用的造型。内置screenplay-standardizer，无需另装。
3. 仅标准稿/资产任务到相应交付结束；完整workflow先记录按人数拆分或自定义范围的意图，资产交付后确定正式分段。按人数拆分先按字数确定目标切点，再在目标点附近审查事件连续性并全局择点；分工规则维护于[剧本分工与范围映射](references/script-partition.md)。
4. 按场完成文字分镜和独立审阅，按已授权分段依次交付，每段完成即给出独立TXT链接、单元数量及总时长。当前段本地交付后继续下一已授权段；选择同步时按画布规则分别处理入队或待同步状态。局部续做延续当前轮序号，整段重做统一增加轮次后缀；指定单元修改和重试保留身份。
5. 画布同步共用后台队列；新任务在本地复用官方SDK编译资产/视频节点及引用，按批次提交并逐节点回读验收，缺图片仅记录。完成及异常独立通知；视频准备缺失资产不超过10个时自动补建，超过10个时停止该任务并报告明细。复用已完成资产只核验视频引用，不重验其生图提示词或图片就绪。主流程不主动询问上传图片，明确上传请求仍保留独立能力。停止/暂停不会因安装或恢复查询自动解除。

新项目的outputs默认只发布最终标准剧本TXT、资产分类提示词TXT、资产台账JSON和各分段分镜TXT。正式原件、过程修订、预览和审阅记录保存在work，发布文件使用稳定名称，具体核验及更新规则见[输出保护](references/execution-contract.md#本地调用与输出保护)。

新稿固定抬头采用项目保存的`custom-v1`，从`video-header.txt`读取两行原文；原始历史资源继续按各自policy读取，旧回执导出不迁移。

格式继续使用视觉抬头、保存的风格、实际资产名与现有镜头版式。单元组织、时长与摄影选择统一见[创作规则总集](references/storyboard-rules.md)，不在入口另设规则。保留原台词、声源、事件因果及动作结果，不以镜数、时长或表现配额新增剧情。

## 安装与运行

需要支持本地Skill的Codex和Python 3.9+。完整剧本的风格与比例均保存后才检查当前Python的PyYAML，缺失时安装并验证，已有可用版本不升级。画布操作另需Node.js、npm及官方CLI，按需授权。

安装到当前CODEX_HOME下的skills/seedance-scene-director；已有安装先在Skills目录外备份，确认没有活跃Canvas写者，再完整替换并核对VERSION和文件摘要。不混用不同包的模块，不写真实项目到Skill目录。公开版本从[项目仓库](https://github.com/loriyai/seedance-scene-director)选择明确tag，本地修订不会自动发布。

同一命令内复用已验证的设计基线、编译结果、分镜解析和索引，独立入口及提交边界继续核对输入变化，质量门禁保持完整。作者闸门返回完整错误定位，便于按根因集中修订。Windows交接包遍历支持长路径，扫描错误明确拒绝。各项执行规则仍维护在所属模块。

Python回归入口为 `scripts/self_check.py`，Skill元数据另用quick_validate检查。结构、离线测试和来源覆盖不证明实际视频效果或整体提速；耗时以本次实际事件为准。
