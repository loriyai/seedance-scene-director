# 逐场复核与人工确认

已确认人物名后带原文括号提示再接冒号的对白，如`林舟（低声，语气平静）：我知道。`，按明确声源识别；中英文括号/冒号兼容。覆盖核对不把角色标签当作台词，但会单独检查括号中的原情绪、微动作或声音类型是否在对应台词标签保留，不能删除提示来通过校验。OS/内心OS/内心想法的等价标签可规范化，其他提示只忽略标点空白，不改词。所有成员已逐字列在人物行且由顿号连接、紧接冒号或对白引号的明确联合标签，如`甲、乙（齐声）：你好。`，按完整联合声源识别；未知成员、重复成员或动作句不由此推断为联合发声。其余复杂声源仍人工复核，单人分支不变。新复核使用review_version 9，加入下述源片段映射并保留场界检查；不复用旧算法缓存，既有说话人/段落决定在原文、上下文和成稿仍匹配时继续使用，已绑定项目及旧分镜不自动迁移。既有观察导入的不可变v7/v8快照仍可核验，不能拿旧快照给新导入或新装配放行。

先运行 `screenplay_review.py`。报告的 `paragraph_map` 对每个原文段落列出对应的逐场稿行号；纯角色名、独立 OS/画外音、空段等注明具体原因。`coverage_missing` 与 `coverage_extra` 必须处理。`speaker_items` 同时包含原文引号和无引号成稿台词，列出原文片段、成稿行、说话人提示及待核原因。自动提示只接受明确角色标签或姓名紧接明确发声谓语的简单句；多角色、多个引号或复杂从句无法唯一归属时进入人工确认。没有明确提示时不得仅凭动作主语或“看向某人”自动认定说话人。

```text
python scripts/screenplay_review.py <workdir> --report <review.json> [--decisions <decisions.json>] [--previous-report <old-review.json>]
python scripts/screenplay_review.py <workdir> --scope sample --scenes 1 3 8 --report <sample-review.json>
python scripts/screenplay_review.py <workdir> --scope partial --report <partial-review.json> [--previous-report <prior-review.json>]
python scripts/screenplay_io.py assemble <workdir> --review-report <review.json> --output <script.txt>
```

人工决定用报告中的 `decision_key` 作键。复制同一条的 `decision_template`，确认后增加 `speaker`；原文引号是叙述中的引用、并非台词时增加 `classification: 非台词`，此时该引号不能已经匹配成稿台词。示意：

```json
{
  "报告中的 decision_key": {
    "source_text": "我在这里",
    "context_before": ["阿明回头"],
    "context_after": [],
    "draft_text": "我在这里。",
    "speaker": "阿明"
  }
}
```

台词字词必须仍与原文一致；`speaker` 决定仅确认归属，不豁免漏文、额外文字或台词差异。脚本会逐字比较决定中的原文片段、前后文、成稿台词；任何一项变化都会使旧决定失效，需重新确认。决定键由片段、相邻上下文及场景标题内容计算，不依赖原文段落号；只在内容和上下文仍匹配时复用。

原文中确属非剧情正文、但脚本未能自动识别的纯格式提示，可以在 `decisions.json` 的 `paragraphs` 对象中按该段 `decision_key` 写入报告中的 `decision_template`，并加具体 `reason`。不得用它跳过动作、台词或情节内容。该决定同样在原文和上下文改变后失效。

同一份决定文件也可包含上面的说话人确认、`paragraphs`、`fragments`和`boundaries`。改稿重跑时传入旧报告 `--previous-report`：只有复核算法版本一致，且原文场景内容、逐场稿内容及该场相关决定未变化的场景可直接复用检查结果。旧说话人/段落决定仍允许内容相同的段号平移；使用下述显式片段映射时，原段坐标也必须相同。算法版本升级或其他场景变化时重新检查。`assemble` 强制核对当前原文和逐场稿摘要；旧报告不能用于变化后的文件。

## 源片段跨目标覆盖

默认仍按原文顺序核对连续正文。一个原段实际拆到标题、动作、台词或声音标签时，在`decisions.json.fragments`中按该段的`fragment_key`保存显式映射：复制报告的完整`fragment_template`，增加具体`reason`和非空`fragments`列表。不要使用`paragraphs`纯提示决定来绕过正文。映射与纯提示决定不能同时作用于同一原段。

`fragment_template`绑定`policy: source-fragments-v1`、原`paragraph`、逐字`source_text`、前后文、整场原文`source_hash`和实际场稿`draft_hash`。每个片段提供`source_range`、逐字`source_text`以及`target`；目标包含`kind`、实际文件`line`、`range`、逐字`text`。行号从1开始；字符范围为零基半开区间，按Python字符串字符计数，包含原始空白，不能按字节或压缩后的文字定位。目标范围以保存文件的整行计算，包含前面的`△ `或人物标签所占位置，但选中范围须落在对应正文、地点或声音标签内部。

例如原段1为`阿明垂眸os`，段2为`“我知道。”`；成稿第3行是`△ 阿明垂眸。`，第4行是`阿明(内心OS)：我知道。`。复制该段的完整模板后，增加以下字段：

```json
{
  "reason": "已实读确认末尾os属于紧邻的阿明内心台词；垂眸动作保留在正文。",
  "fragments": [
    {
      "source_range": [0, 4], "source_text": "阿明垂眸",
      "target": {"kind": "action", "line": 3, "range": [2, 6], "text": "阿明垂眸"}
    },
    {
      "source_range": [4, 6], "source_text": "os",
      "target": {"kind": "cue", "line": 4, "range": [3, 7], "text": "内心OS"},
      "speaker": "阿明",
      "dialogue_source": {"source_range": [2, 2], "source_lines": ["“我知道。”"]}
    }
  ]
}
```

这两项字段须并入模板，不能单独替代模板。`dialogue_source.source_range`是从1开始、两端包含的原段号范围，与字符范围不同；它可覆盖紧邻的多段原台词，`source_lines`须逐段逐字匹配。台词还须通过原有`speaker_items`说话人复核；映射不代替人工归属决定。

对于`转场 泳池 傍晚`，可把字符`[3,5]`的`泳池`映射到`场景1-日-外-泳池`标题地点的`[8,10]`，把`[6,8]`的`傍晚`映射到实际动作行`△ 傍晚。`的`[2,4]`。转场语法仍由现有解析器识别；地点无需在动作里重复。标题仅接受场首转场段的实际地点片段，不能消费标题固定格式中的“场景”“日”“内”等字。

校验要求：除已解析的格式前缀外，原段全部字词必须各消费一次，片段不得重叠或倒序；正文目标沿全场原文顺序消费，段内及跨段都不能重复占用同一标题、正文或声音标签范围。动作、时间和台词不允许删除或改词；保留现有标点/空白比较原则，实际语气仍须实读。新增或遗漏正文继续进入`coverage_extra`或`coverage_missing`。

`cue`通道的源片段只接受段末的既有声音语法`OS/O.S./画外音`；目标可使用已支持的OS等价标签。它须完整对应真实声音标签，并逐字绑定人物声源和紧邻原台词。原文与成稿都不能跨过另一个动作或台词去借用声音标签；紧邻原台词有明确人物标签时必须一致。`低声`等未在该迁移语法内的内容、动作句或`os拔刀`不能借此删除。复杂声源由作者实读并独立确认，不从动作主语自动推断；不能证明归属时保留待核或保留原文。

报告在`paragraph_map`中保留实际片段和目标范围。映射的增加、删除、修改均进入该场`decision_hash`；原文、上下文、段号或场稿任一绑定内容改变后，旧映射不能复用，即使只是场稿另处变化也应重新核对并保存当前模板。不得刷新旧hash冒充重审。v7/v8算法报告不用于新装配、新观察导入或新项目绑定；历史观察快照继续原样验证，已有项目、分镜和回执不自动重写。

## 首批样本与逐场出口

先选能覆盖原稿实际格式的少量代表场，使用`--scope sample`校准，再分批保存和使用`--scope partial`检查已有草稿；`--scenes`按真实场次号选取，不要求样本连续。样本只读当前原文和指定逐场稿，不改source.json；场次号/原文范围必须合法、无重复、无重叠。每场均先调用与assemble相同的标题、人物行、正文确定性检查，不能先发样本通过再到资产入口发现重复人物。人物槽位按完整源人物名唯一，不把基础和佩戴/换装状态放成两个人；不把记者1、记者2、记者一等不同源名自动合并。佩戴状态仍使用原显式形象轨迹规则。

局部报告成功状态分别为`sample_passed`和`partial_passed`，带`scope`、实际检查的场次和`coverage_complete: false`。它们不能用于assemble或bind，也不代表全文通过。最终必须运行默认`--scope full`，连续覆盖全部原文且状态为`passed`。full禁止`--scenes`。同一算法版本的有效样本/批次场景结果可由最终full报告按原文、草稿和决定哈希复用，但full仍重新验证完整范围。

## 移动载体场界复核

先判断原文是否实际转场，再给场标题和内外标记。分别核对场界与[地点命名依据](../INSTRUCTIONS.md#地点称谓与移动过程)：标题优先保留原文明示的主要地点，动作中的连续行驶不自动成为地名后缀。实读LOC/SET名称时同样核对原称或必要消歧依据；标题、台账字段相互一致不代表自行扩写的地点名合理。机位进入车内、转向后排、车窗内外反打属于镜头空间变化；车辆仍是同一可移动实体，不因镜头变成独立地点。原文明示驶往新地点、跳时或转入独立事件时仍可分场；“转场”字样也须核对究竟表示真实叙事变化还是单纯切镜，不能一律保留或一律合并。

新报告的`boundary_items`对相邻场标题中的车内、老头乐内、车厢等移动空间发出风险项；样本/局部检查也查看已存在的直接相邻场稿。未处理项进入`counts.scene_boundary`并使报告为`needs_review`。有限词表只能发现部分风险，未出现诊断不证明全部场界合理；写者仍须核对全部场界。它不自动合并、不改标题、不建PROP/LOC/SET，也不替代实际阅读。

合并时修改逐场稿和连续原文范围、重排场次、核对合并后人物行，然后重新review和prepare观察。确需保留时，在同一`decisions.json`的`boundaries`对象中，用该项`decision_key`保存完整`decision_template`，另加：

```json
{
  "outcome": "retain",
  "reason_kind": "location_change",
  "source_paragraphs": [12],
  "evidence": "车驶入金荣街。",
  "reason": "原文已离开前场路口并进入金荣街，本场继续车内对话；场界依据是实际地点变化。"
}
```

此片段须并入报告提供的完整模板。`reason_kind`可选`explicit_transition`、`time_change`、`location_change`、`event_discontinuity`、`independent_vehicle_space`；最后一项仅用于原文确把载体内部作为独立叙事空间的情形。引用须在相邻两场范围内、段落连续、证据逐字匹配。模板同时绑定两侧标题、原文范围、原文与场稿摘要及邻接上下文；任一改变须重新复核。脚本只验证决定与证据绑定，不能证明所写理由在语义上成立，不得批量填通用理由自动放行。实际裁决应在样本/逐场出口完成，避免资产生成后再重做SC/LOC/SET。

## 原文解析兼容与差异诊断

原文始终逐字保存。`source_compat.py`仅创建解析视图，识别成对的`「」`、`『』`、`“”`、`‘’`和ASCII双引号，保留嵌套引号内正文；支持已知声源的`角色OS：`、`OS 角色：`、`角色 O.S.：`等明确位置。独立OS前缀仍须保留为对应成稿声音提示。错闭、孤立闭引号或未闭合只报告具体边界问题，不猜测配对、不改原文。`parsing_transforms`记录解析类型、原文和位置，不能把它当成已修改原文。

只有独立的`第十章`、`第12集`等纯结构编号可分类为格式提示；`第十章 林舟回家`等含标题文字的行不自动忽略，须保留内容或按既有原文/上下文绑定的`paragraphs`决定确认其纯提示性质。若纯编号字样已作为成稿台词保留，也按正文处理。

报告的`issue_counts`分别统计源格式问题、过期决定、文字对齐、人物契约、真实声源归属待核及声音分类；`counts.format_hints`单列已识别的格式提示。总`speaker`数仍表示待处理记录数，不表示同等数量的错误台词。先处理可确定的格式问题，再复核真实歧义；不放宽复杂从句归属来压低计数。

`punctuation_diagnostics`列出可直接对齐的台词/动作标点和空白差异，供写者在冻结逐场稿前核对。它不会自动改字或把有依据的补标点一律判错；`不，是他。`与`不是他。`这类差异须实读确认，不能只见字词覆盖通过就忽略。先完成补标点、人物槽位与声音分类核对，再运行full及assemble；assemble后的交付核验不替代这一出口。

## 非人物有语义播报

人类角色对白、可见集合共同发声、非人物有语义播报和普通无语义音效分别处理。不得仅凭“电话”“系统”等名称推断非人物，也不得把真实人物画外音改成机器声。写者结合原文确认自动播报后，标准稿使用`电话提示音(非人物播报)：原话`，声源名不进人物行，不为它创建人脸资产。原话连同标点逐字保留；不添加原文没有的“声效”等正文。

第一次复核会生成声音分类待处理项。复制该项`decision_template`，保留其中`source_text`、前后文、`draft_text`以及完整`source_lines`，再增加：

```json
{
  "classification": "非人物播报",
  "source_label": "电话提示音",
  "reason": "原文明示来自电话自动提示，无人物视觉身份"
}
```

上述字段须合并进原模板并以其`decision_key`保存，不能仅保存示例三项。原文同段声源名、上下文或成稿变化均需重新确认；分类决定不豁免文字/标点差异，也不能给仍列入人物行的声源放行。非人物播报进入专门声音记录与排声，不能因为不建人物资产而丢失发声文本。真实无法确定的声源保留待核；普通音效仍依原动作/环境记录，不套用播报台词格式。
