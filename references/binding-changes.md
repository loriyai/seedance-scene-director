# 已绑定项目的来源与资产变更

`director.py bind`只支持没有`session.json`的新项目目录。当前没有同目录`rebind`命令。仅存放位置改变而绑定内容未变时，使用[项目迁移](project-portability.md)，不属于内容重绑定；导入保留原历史并验证位置等价。来源或台账内容实际变化时仍按本页处理，迁移接口不解除内容校验。绑定材料变化后停止旧绑定的新生成与提交，不能直接更新session里的摘要、台账或来源坐标来绕过校验，也不能声称已在原项目完成重绑定。

运行项目时发现原稿、视频风格或视频比例与当前已保存版本不一致，立即暂停受影响的后续阶段并提示用户选择处理方式。用户未完成选择前，不重算分段、资产或分镜，不覆盖旧版本，不继续提交画布任务。确认采用新版本时，按本页保存新的来源、风格或比例快照并重新核对受影响范围；确认沿用旧版本时，继续读取旧快照；取消或暂不处理时保留当前检查点并停止后续生产。

先根据变更制作可审阅的新版本材料：纯制作显示名变化不重写剧本、台词或说话人；候选缺漏只补相关资产及必要场次，完成候选preflight、设计/局部design和最终验证；剧情/台词变化按标准化与资产迁移流程保存新旧对应。未变的逐场报告和有明确依赖且仍有效的设计可复用。旧材料必须保留，不在绑定文件原路径上覆盖。

当前已支持的完整绑定路径是：在新的版本项目目录保存风格，用通过验证的新标准剧本、source、review与台账执行首次bind。旧项目的session、编号、范围历史、receipt、图片、画布映射及冻结任务保留原版；新版本目录不会自动继承旧项目的单元历史或画布连接。不得通过复制session创建名义上的新绑定；同一批分镜须使用同一有效来源版本。新项目若操作画布，仍按用户明确目标与范围建立连接和映射；不自动重复建节点、不迁移或删除旧映射。

用户要求在同一项目中保留历史、节点映射并直接更新来源/台账时，先完成局部变更材料，再明确报告当前工具缺少该迁移能力；不得声称迁移已完成，也不得要求重做未受影响的全剧材料。可供用户审阅的材料应说明变更资产/场次、保留ID、受影响单元及待迁移映射。选择新的版本项目路径后才采用上述已支持绑定方式。

未来同项目重绑定必须完整实现并测试以下语义后才能开放：按绑定版本保存来源、资产和风格快照；旧receipt始终按原快照渲染；明确迁移有效单元及来源坐标、稳定编号和范围历史；校验真实节点映射；运行中的冻结任务继续原摘要且不被新绑定误记为已完成；迁移原子保存、失败可恢复。仅改文件hash或给bind增加覆盖开关不满足这些要求。
