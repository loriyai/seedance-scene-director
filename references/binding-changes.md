# 已绑定项目的来源与资产变更

`director.py bind`只支持没有`session.json`的新项目目录。当前没有同目录`rebind`命令。仅存放位置改变而绑定内容未变时，使用[项目迁移](project-portability.md)，不属于内容重绑定；导入保留原历史并验证位置等价。来源或台账内容实际变化时仍按本页处理，迁移接口不解除内容校验。绑定材料变化后停止旧绑定的新生成与提交，不能直接更新session里的摘要、台账或来源坐标来绕过校验，也不能声称已在原项目完成重绑定。

来源事实使用库内已有SET/PROP但缺少精确引用关系时，使用[精确来源的既有参考](storyboard-text-format.md#精确来源的既有参考)；该入口只扩当前候选的来源资格，不重写绑定材料。

已授权的泛称人物制作分配、群板个体选择和必要的候选级补充人物设计，使用[来源人物的制作对应](storyboard-text-format.md#来源人物的制作对应)。其精确来源、授权、身体与设计随候选和回执绑定，原台账、源文本及历史回执保持原样；不是同目录重绑定。真正变更源事实、已设计身份或正式台账内容时仍执行本页变更规则。

来源动作中明确存在的匿名静默背景群体或动作参与者，满足文字充分性与授权条件时，可按[精确来源的静默人物声明](storyboard-text-format.md#精确来源的静默人物声明)登记当前候选的逐记录`prompt_only`资格。声明不重写来源、台账、场次人物集合或项目绑定，不授予图片及声音资格；新候选与历史回执分别按该节执行授权、范围及冻结兼容核对。

既有道具仅需按[连续性规则](storyboard-rules.md#连续性)跨场低干扰携带时，使用[文字分镜侧车](storyboard-text-format.md)的`continuity_props`声明当前场制作延续。该入口以既有PROP、本场合法CHAR、前序精确证据及作者明确选择的状态为界，绑定到当前候选和独立审阅，在正式提交时随对应单元保存。原文来源、资产设计和台账关联据实保留，因此仅增加这类候选引用资格无需重建项目绑定。真正修改来源、台账或资产内容时继续按本页其余规则处理。

`context --authoring-trace`只读展示声明的本场资格，`bind-trace`绑定作者已有决定，`check`、`preview`及`commit`校验同一组声明。结构通过仅确认ID、范围、前序版本和精确证据可定位，独立主审仍须阅读锚点至目标场之间的相关来源与已提交末态，核实持有关系以及是否发生转手、遗失、消耗、损坏或其他状态改变。同一单元同时出现持有人和道具不足以证明持有关系。主审将实际结论纳入当前候选的既有审阅流程。

前序单元版本或当前声明变化时，未提交候选须重新核对相关影响并绑定匹配的审阅。已提交单元与历史回执保留当时的声明和输出，可以按原记录重新导出。重试沿用原请求身份，改变延续声明属于候选内容变化。当前程序声明的持有主体为本场合法CHAR，同一人物的服装或佩戴版本按既有`appearance.identity`与`incarnation`显式身份关联核对。仅同名、仅同说话人或缺少显式身份均不足以跨CHAR ID延续，其他实体结构须依现有协议的实际支持范围处理。

先根据变更制作可审阅的新版本材料：纯制作显示名变化不重写剧本、台词或说话人；候选缺漏只补相关资产及必要场次，完成候选preflight、设计/局部design和最终验证；剧情/台词变化按标准化与资产迁移流程保存新旧对应。未变的逐场报告和有明确依赖且仍有效的设计可复用。旧材料必须保留，不在绑定文件原路径上覆盖。

当前已支持的完整绑定路径是：在新的版本项目目录保存风格，用通过验证的新标准剧本、source、review与台账执行首次bind。旧项目的session、编号、范围历史、receipt、图片、画布映射及冻结任务保留原版；新版本目录不会自动继承旧项目的单元历史或画布连接。不得通过复制session创建名义上的新绑定；同一批分镜须使用同一有效来源版本。新项目若操作画布，仍按用户明确目标与范围建立连接和映射；不自动重复建节点、不迁移或删除旧映射。

用户要求在同一项目中保留历史、节点映射并直接更新来源/台账时，先完成局部变更材料，再明确报告当前工具缺少该迁移能力；不得声称迁移已完成，也不得要求重做未受影响的全剧材料。可供用户审阅的材料应说明变更资产/场次、保留ID、受影响单元及待迁移映射。选择新的版本项目路径后才采用上述已支持绑定方式。

未来同项目重绑定必须完整实现并测试以下语义后才能开放：按绑定版本保存来源、资产和风格快照；旧receipt始终按原快照渲染；明确迁移有效单元及来源坐标、稳定编号和范围历史；校验真实节点映射；运行中的冻结任务继续原摘要且不被新绑定误记为已完成；迁移原子保存、失败可恢复。仅改文件hash或给bind增加覆盖开关不满足这些要求。
