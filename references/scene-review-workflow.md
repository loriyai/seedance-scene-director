# 场次前检与保守增量复核（B）

本流程用于新生成与用户选定的局部修改，标记 `workflow_policy: scene-review-b-v2`。旧单元、已提交receipt和运行中的Canvas冻结任务不迁移。输出仍是reference-v3，原剧情、台词、时长、固定抬头和菜单规则不变。

## 先确定制作依据

每场开始时，从已绑定原文、台账、设计和前序有效末态提取一份简短制作依据：当前实体及合法形象、必要位置与遮挡结构、持物/接触/衣物等持续状态、声源与自然分句。复用已有continuity和audio字段；只记录影响本场判断的事实，不再抄写整段剧情，不补造坐标或未明示动作。已确认的用户合并/形象选择纳入当前绑定。

身份或进入态存在真实矛盾时先解决依赖，再写相应镜头；不能先扩写几十镜再统一选形象。实体在场、画内可见和焦点分别判断，空间关系确定后再选择构图。绘制机位无需增加用户确认；程序也不宣称能自动证明机位可拍。

## 关键触发、时间窗与渲染前检

1. **起草前提取关键触发。**只列本场会影响动作或回应时点的少量关系及原文依据，例如“劝告结束 → 抬眸 → 回应”。明确区分原文明示先后、为忠实呈现而选定的先后和可同期成立的状态；普通文字排列不能自动变成严格事件链。关系只留后台，依据可并入purpose；真正约束生成的先后还须写进会被渲染的text、构图或切镜衔接，不能只存在于purpose。
2. **先给顺序动作留出可表演时间，再定摄影。**对这些关系核对触发完成时点、动作可执行区间、后续起音与切点；若安排“先抬眸再回应”，抬眸和回应不能同一时刻起始而又没有动作时间窗。窗口按本次动作与呈现判断，不设通用生理阈值，也不为每次反应强加停顿；可以同期的动作与声音仍按max计时。必要时移动起音、重分自然语句或切点、调整合法单元时长，并重算发音单位、净语速与停顿账；仅加“说完后”“继而”而保留冲突时码不算修复，不用拉长尾字或补动作填空。沿用既有整数镜头轴及片段落镜规则。
3. **冻结前实读同版实际渲染和后台时码/状态。**执行下文“声音放行与冻结前关联检查”的统一检查与绑定，不重复维护另一份状态表；purpose中正确的意图不能代替实际呈现。

这三项是作者的语义前检，不生成自动passed，不替代首次独立逐镜实读或原有结构校验。审阅者取得同版本渲染预览、时码和来源，核对关键关系是否实际可读、可执行。修后声音变化仍按下文整单元边界复核，其他依赖按真实影响传播；未变的有效证据继续复用。

## 身份与声音前检

人物视觉引用、声音身份与普通提及分别处理。实际图像资产使用稳定ID；声源遵循原文record；站位轴线、未到场、远端等普通提及不得自动增加subjects/character_ids。完整名称由现有渲染器展开，prompt_only按既有规则输出普通文字。

`storyboard_preflight.py`在每镜完成时扫描最终输出字段中的裸名称和已审别称，原台词和来源引文不参与替换。单字姓、数字代号和泛称不能按字符串命中自动选人；地名、书名等可以登记具体保护依据。执行者对候选作与字段原值摘要绑定的判定，不能全局replace或靠添加人物声明消除警告。判为真实视觉引用的候选须修为正确引用；原值变动后旧判定失效。

先按完整语义分句确定实际念法与发音单位、片内停顿和片间间隙，再调用已有estimate安排时间及摄影。数字、英文、编号等即使只有一个片段也须核算。中文可以默认按可发音字数计；特殊读法须提供实际读法与依据。实际念法只存后台，不改原台词。

明确登记的单位合计和停顿账矛盾是硬错误；实际净语速超档、长气口等仍是需要具体依据的警告。结构status=passed不等于允许展开摄影；须同时readiness.status=ready。总停顿等于片内停顿合计加片间间隙，不能再叠加基线标点停顿；切镜、表情和breath_basis不会自动产生秒数。完整单元仍检查逐字台词、时码和自然切口；recording沿已有实测规则，不用文本估算覆盖录音。

## 场次冻结与集中修订

作者逐单元自检并完成上述关键触发、时间窗和实际渲染前检后继续；一场或一个必要的跨场连续段准备好后，保存不可变快照，进行首轮独立逐镜实读。交接范围含同版本渲染预览、该场单元及前后连接、对应原文、声音和资产依据；无需反复读取无关全剧材料。跨场单元只能由一个写者负责。

审阅者只输出具体判断和问题，不修改正在写的草稿。每项问题包含快照摘要、镜头/字段、原值摘要、原文依据、根因、建议和关闭条件。同根因可以合并，保留所有受影响镜头；同字段修法冲突先由主代理裁决。先收齐冻结范围的反馈，交给唯一写者集中修订。真正阻塞身份、来源或后续连续性的错误立即报告，不等整场结束。

修订必须针对当前版本，按原值精确应用；不匹配时保留冲突，不能覆盖新稿。修改动作/空间时按下述统一冻结前检查核对真实关联字段；未受影响的光照、摄影和持续状态可保留，不能机械重写全部字段。问题只有在实际修后复核满足关闭条件时才能关闭。集中一次修订是目标，残留矛盾或新问题仍须处理，不因轮数放行。

按场冻结是证据和写入边界，不是连续性隔离墙。后续草稿引用明确的前序版本；前序变化时相应后续依赖失效。待审期间仅继续不依赖未决状态的工作，不让未接受连续稿无限向后扩展。

## 复用已有逐镜判断

`scene_review.py`组合已有真实判断，不能产生语义通过。首次每镜均须实读；后续只复制与旧冻结快照、相关依赖精确一致且有具体依据的passed判断。旧报告必须与旧快照绑定，缺镜、重复、乱序、未知依赖或输入变化不能自动接收。

声音变化仍保守重审所在单元及必要连接，不实现声音事件级细分。局部摄影修改可使用下述已审依赖声明细分；历史镜头不强制补ID。插镜、删镜或重排当前保守失效，不把旧“第2镜”判给新“第2镜”，不做文本相似匹配。

| 变化 | 复核边界 |
|---|---|
| 裁幅、机位、光照、动作描述 | 本镜及视线、轴线、遮挡、匹配动作相关连接；不固定前后各一镜 |
| 发音单位、停顿、语速、声源、delivery或分段 | 首版重审声音所在单元及必要连接，覆盖跨镜继承 |
| 持物、接触、位置、衣物、形象或在场状态 | 向后传播到有效状态重新一致，收敛单元须重审；未变且已有原文依据、实际审阅通过的独立reset可作为边界复用，新增或改变的reset须审 |
| 原文、说话人、资产或设计依据 | 所有实际依赖项；改稿仍先走原有重绑定流程 |
| 来源覆盖、插删镜、拆并单元 | 检查覆盖、时码和声音分配及相邻边界，位置漂移不模糊匹配 |

机器识别的影响范围是保守建议；没有登记的摄影/声景关系不能据此宣布无影响。依赖不清楚时扩大到相关场次或连续分量，必要时人工扩大范围；不能为了缩范围发明reset。全局规则或风格变化可使整个当前请求失效。姓名格式修正同样先重审受影响对象，不加入无边界语义归一化豁免。

精细复用使用可选 `review_dependencies`，它必须随首轮实际镜头一同交给独立审阅者，成为旧target的一部分。每镜有本次草稿内唯一且稳定的 `review_id`（不改正式编号）；单元声明 `{policy:"shot-dependencies-v1", complete:true, basis:"具体核对哪些轴线、视线、遮挡、动作匹配及公共参照的依据", links:[{from:"镜头ID",to:"依赖该镜的镜头ID",kind:"axis|eyeline|occlusion|action_match|composition|state|other",basis:"具体关系"}]}`。ID在当前请求内唯一；完整声明是审阅者需核实的事实，不能因想提高复用率而遗漏关系。

`shot_dependencies.py`将本镜、实际进入状态、完整单元声音及片段、来源、相关资产/设计、公共条件、相邻时码和显式依赖闭包进行精确比较；单元边界保留前后实际镜头依赖。变化只使实际依赖项待审。连续状态按逐镜变化重放；到进入状态及依赖重新一致之后才可复用，恢复状态的那镜仍待审。缺声明、缺历史依据、未知关系保留原保守范围；图有声明但无效时扩大，不能退回更宽松路径。整体原文绑定或规则改变仍可整批失效。

传入首轮审阅完成时另存的旧报告规范摘要 `--old-report-sha256`，工具拒绝不匹配的旧报告。旧快照/报告不变、每镜依赖相同、真实具体passed依据三者同时成立才复制。输出每镜旧target、旧报告及快照摘要、核对过的依赖和具体失效原因。新报告保存 `reuse_evidence`，CLI使用旧快照/报告的绝对文件引用及摘要，故这些文件须不可变且可访问；不嵌套复制历轮大报告。最终gate重新计算镜头与警告处置的复用范围并核对复制的原判断；不自动生成任何新语义通过。摘要用于检测存储漂移，不证明作者确实实读；该责任仍由首轮独立审阅承担。

警告只有原对象、摘要和相关输入均未变时才能复用旧处置。相同警告文字不能证明新时码或新表演仍合理。增量准备后的报告顶层、四项总体判断保持pending；主代理结合当前来源覆盖、边界和问题关闭情况实际确认，不脚本批量填passed。

## 工具接口

以下命令在后台执行，文件均置于项目工作目录；每轮使用新文件名，快照与旧报告不可覆盖。`<batch-v1.json>`保留原选定顶层span及已完成units前缀，每单元登记`workflow_policy: "scene-review-b-v2"`，每镜登记真实`scene_id`。`--partial`只用于编写中的前缀，不能跳过来源或已完成单元的结构检查；最终verify和commit不接受partial交付。

```text
python <skill>/scripts/storyboard_preflight.py --project <project> --plan <声音计划.json>
python <skill>/scripts/storyboard_preflight.py --project <project> --request <batch-v1.json>
python <skill>/scripts/director.py check --project <project> --request <batch-v1.json> --partial --require-workflow
python <skill>/scripts/scene_review.py freeze --project <project> --request <batch-v1.json> --out <场次-v1-快照.json> --partial --require-workflow
python <skill>/scripts/review_gate.py prepare --project <project> --request <batch-v1.json> --report <场次-v1-审阅.json> --partial --require-workflow
python <skill>/scripts/scene_review.py merge-issues --snapshot <场次-v1-快照.json> --issues <主审问题.json> <专项问题.json> --out <集中问题.json>
python <skill>/scripts/scene_review.py revise-plan --snapshot <场次-v1-快照.json> --merged <集中问题.json> --out <修订计划.json>
python <skill>/scripts/scene_review.py prepare-incremental --project <project> --request <batch-v2.json> --snapshot <场次-v1-快照.json> --old-report <场次-v1-审阅.json> --old-report-sha256 <旧报告规范摘要> --out <场次-v2-待审.json> --provenance <场次-v2-复用来源.json> --partial --require-workflow
```

`merge-issues`只传实际存在的问题文件。首轮由审阅者实读后填写pending报告中的逐镜结论；问题单单独保存。修订计划只列待改项与冲突，不执行修改，不自动关闭问题。修订者按计划修改新版本，复核者再完成增量报告的pending项。进入下一场时继续冻结新的完整前缀；前序尚未解决的依赖不能当作已接受状态。最终完整批次去掉`--partial`，进行完整check，使用同一增量工具组合有效证据，实审剩余项与总体检查，再执行完整review_gate verify和commit。

声音计划是含正常`audio`及`audio_plan`的单元对象，可暂时没有shots。`--project`提供已绑定原文与台账；离线`--plan`仅核对计划内部一致性，不证明来源覆盖。示例片段字段如下（只演示接口，不可复制为制作依据）：

```json
{
  "audio": [{"record":"L1", "text":"给我100元。", "units":5, "start":0, "end":1.5, "pause":0.34, "speed":"常速"}],
  "audio_plan": [{"record":"L1", "parts":[{
    "text":"给我100元。", "start":0, "end":1.5, "pause":0.34,
    "spoken_readout":"给我一百元", "spoken_units":5, "spoken_basis":"按金额读一百元"
  }]}]
}
```

绑定原文校验时还需真实unit span、scene_ids和声音身份。完成摄影后把各parts放进对应镜头的`dialogue_parts`，每项增加record，保留实际读法和pause；新v2必须保留audio_plan且与最终片段一致；修改从计划同步，不允许删除计划绕过一致性检查。速度估计通过不代表表演通过。

身份候选保留为待审warning。确需登记分类时，将`identity_decisions`放在相应unit内，每项包含：`field`（如`shots[0].camera`或`global`）、`value_sha256`（字段原字符串UTF-8的SHA256）、`term`、`start`（从0开始的字符位置）、`classification`及具体`basis`；人物分类另含真实`asset_id`。分类只允许visual_reference、voice_reference、prose_mention、protected_text、not_character。视觉引用仍必须写成合法资产引用；普通提及不得转成出镜主体。字段改动后须重新判断，不能只更新摘要保留旧结论。

审阅问题单推荐绑定完整快照：

```json
{
  "snapshot_sha256":"取自冻结快照",
  "issues":[{
    "root_cause":"具体共同根因",
    "target":"1:1",
    "field":"shot.composition",
    "basis":"该镜原文、状态或摄影关系的具体证据",
    "requested_change":"针对该字段的明确修订要求",
    "closure_condition":"修后可逐项核对的关闭条件"
  }]
}
```

也可提供数组，但每项须附`expected_sha256`，等于冻结快照对应target字段经`scene_review.digest`计算的摘要。此摘要是规范JSON摘要，和身份候选的原字符串摘要不同。无版本绑定、错误快照或过期字段反馈均拒绝。生成的复用来源文件保留旧报告摘要、原审阅者、每镜失效原因、复用/待审数量；它是审阅追溯记录，不是新语义审批。

## 最终验收与记录

新B请求在check、review_gate和commit使用 `--require-workflow`；显式标记的单元即使未传此选项仍执行前检。该选项只检查本次选中的新/替换单元。兼容入口保留旧调用，旧receipt幂等导出优先使用原记录。

完成最终全批结构检查和当前警告全集核对，生成绑定当前请求与上下文的新最终报告，合并有效逐镜证据与本轮实际审阅。最终gate仍要求全部镜头和四项总体检查通过；减少人工重审不会省略全批来源、引用、时长或边界检查。

保留快照、问题单、修订版本、旧判定及复用来源，不改旧摘要。记录首稿结果、每场修订轮次、相同根因重复次数、重审镜数与原因、复用数及交接时间；只报实际测得数据，不承诺固定省时比例。工具输出的复用计数不是成片验收。


## 声音放行与冻结前关联检查（v2详细规则来源）

原写者先完成正常audio、audio_plan及action_plan，不增加声音代理或独立交接。计划含原台词、record与声源、实际念法/单位、自然分句、原文支持的delivery及speed、片内pause、片间间隙、起止及duration。action_plan只列必须先后的动作，字段record、quote、start、end，可用before/after指向声音record；无这类动作可留空数组，由写者说明同期安排。程序检查原文引用、时间边界和已声明先后，不推断所有因果。数字密集、近语速上限、复杂情绪提前重点实读，不固定加缓冲秒数、不虚构停顿。

先运行storyboard_preflight --project ... --plan ...。每个片段必须存在可容纳它的1至5秒整数镜头窗口，程序还检查全单元存在不切断片段的可行整数切点组合；写者继续核对自然分句和切点的可表演性，不预设镜数或一句一镜。报告readiness给出当前input_sha256与pending语义模板，将写者实际判断填写为unit.audio_preflight：reviewer、具体basis、当前input_sha256、warning_decisions。每条警告保留原warning对象和warning_sha256，同时保留模板给出的text及window（start/end/pause），decision=accepted，basis说明具体原句、时窗、净发音/停顿及可表演理由；修改计划后重新检查，已消失警告不保留旧处置。程序不自动填写这些结论。结构硬错误必须修，警告允许有依据的例外，不一律变成内容错误。未处置警告、笼统依据或过期声音/动作绑定会使readiness=blocked，不能展开详细摄影或冻结送审；身份、摄影及历史警告不纳入声音放行条件。

详细摄影的dialogue_parts从当前audio_plan逐项取出并增加record，不维护第二套时间安排。声音、分句、停顿、起音、delivery、动作窗口变化立即重查整声音单元及连接；只有机位/光照变化且这些依赖没变时保留声音处置。摄影需要修改计划时允许反馈调整，先更新计划再同步镜头。独立逐镜审阅仍完整执行。

持续位置与人物关系分别核对。位置优先采用原文支持的稳定参照，如“走廊递杯原处”；“某人面前”是当下关系，参照人物移动后重新判断，不自动编造坐标、布景或移动。离开、转身、交接、站起、跪下等事件需核对text、composition、depth_of_field、visibility、continuity.changes、initial/final和start/end_state真正受影响部分，重点检查垂首、撑伞、抓包起身、跪下、手机在耳侧等暂态预设残留；画外、遮挡、离场分别判断。稳定摄影和光照可以持续。

把以上关联检查与本文件前面的关键触发/动作窗口前检合并执行。冻结前调用 `staging_preflight.py --project <project> --request <request> --output <新的待核清单.json>`，输入单元style必须等于已保存风格。它读取同版实际render_unit输出和后台时码/连续性重放，给每个实际状态事件建立关联字段待核项。写者实读这两份结果后把模板填为unit.staging_review：status=reviewed、reviewer、render_basis、timing_state_basis及每条change_checks的具体basis/status=reviewed。仅填purpose不算核对；程序只检查绑定、结构和逐项记录，不能识别全部自然语言过期关系。内容变化使旧绑定失效；光照不变不要求改写，但相关检查须说明实际保持条件。已声明changes与final仍由原continuity严格重放校验，不独立维护两套结束状态。

本前检由同一写者在独立审阅之前完成，不新增一轮全批人工重审。每场集中反馈后一次集中修订为目标，后续只审实际影响；声音按整单元、状态到真实收敛边界，禁止新增无来源reset缩小范围。新流程使用scene-review-b-v2；历史v1和receipt保留原读校验入口，不自动补造新前检证据。

摄影完成后的声音返修用 `review_metrics.py --before <旧请求> --after <新请求> --provenance <本轮复用来源> --started-at <实际ISO起时> --finished-at <实际ISO止时> --output <工作目录/返修记录.jsonl>` 记录变化单元数、因此失效且已有审阅的镜数和实测返修区间耗时。每次真实返修区间一次记录；不能重复登记同一次返修或填估计时间。无生产数据时不承诺省时比例。
