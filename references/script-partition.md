# 剧本分工与范围映射

本模块负责前置分段意图记录及标准剧本完成后的正式原剧本分工计划，不改写原稿、标准剧本、场次、资产或已生成分镜。前置阶段只保存模式、人数或手动范围；正式分段必须在标准剧本和全稿复核完成后执行。菜单顺序由[资产主流程](asset-workflow.md)维护，分镜入口与历史范围由[分镜工作流](storyboard-workflow.md)维护。

## 选择与人数

三种选择为：按标准剧本场景及原剧本字数拆分、按原剧本字数和安全事件边界拆分、用户手动输入分段范围。前两项在前置阶段只询问并记录“请输入动画参与人数”，接收正整数；人数就是正式分段数量，人数为1时输出完整一段。第三项在前置阶段只记录手动范围输入，正式分段时重新定位和校验；前置记录不创建正式分工计划。

以标准化阶段已保存的原文提取文本计数：所有非空白字符计入，含标点、原有标题及人物标签；空格、制表符和换行不计，工具新增段号和标准化新增文字不计。显示字数与均衡计算使用同一口径，不把该字数当作标准正文范围坐标。

两种方式均按原顺序形成n个非空连续范围，覆盖全文、没有遗漏和重复。在合法切点中，以各段相对平均字数的总平方差最小为均衡目标，使用全局求解，不逐段贪心截断。

- `scene`：切点仅取标准剧本中已复核的真实场界；原文里的换行、“转场”或取景方向不能另造场界。完整场景优先于字数均衡。
- `balanced`：切点由实际阅读者确认能进入下一个分镜单元的自然落点。完整发言、完整动作与紧密刺激—回应不得为凑字数拆开；例如说话尚未结束，或后一句必须急促接答，均不在其间切断。可以同场分工，不能承诺严格等字数。选定范围之外的前后文只作衔接上下文，不重复计入分工正文。
- 人数超过当前合法可切分段数时，提示减少人数，或从场景模式改用字数模式；不能输出空段、擅自减少人数或硬拆事件。安全边界稀少时说明实际限制。

场景模式的最大差距定义为最长段字数减最短段字数。仅严格大于2000时，将候选保存为`needs_confirmation`，提示“按照场景均分差距最大为xx字”，等待“1.忽略差距，直接拆分／2.按照选项2，根据剧本字数来拆分”。第一项确认当前候选，第二项按相同人数重新准备事件切点；不能将超时、脚本生成候选或确认令牌当作用户选择。差距等于2000时直接完成计划。

前置记录的手动范围必须覆盖完整剧本，分段之间不得重叠或存在间隔。输入格式与正式输出格式一致：

```text
A分段：
共n个字
开始：[本分段开始的1—2句话]
结束：[本分段结束的1—2句话]

B分段：
共n个字
开始：[本分段开始的1—2句话]
结束：[本分段结束的1—2句话]
```

正式分段阶段将手动范围重新定位到当前原稿和标准剧本，核对段号顺序、完整覆盖、无重叠、无间隔、非空及锚点唯一性。发现格式错误、重复匹配、倒序、缺口、重叠或无法映射时，提醒用户修改，不生成正式计划。手动范围的首尾摘录必须保留原字词，不能用标准化新增文字替代。

## 安全事件切点

场景模式直接使用已复核场次，不另设审阅表。字数模式在阅读接近目标字数的候选位置时，用一个简短JSON只登记实际候选切点及具体理由；无需逐句、逐镜填写表格。程序验证坐标与完整发言，是否存在急促回应等语义由阅读者判断，`safe:true`不能批量代签。

```text
python <skill>/scripts/script_partition.py boundary-template --project <project> --output <安全切点.json>
```

保留命令生成的`policy`和`sources`，在`boundaries`中增加：

```json
{
  "offset": 180,
  "source_position": [12, 0],
  "safe": true,
  "reason": "该次发言完整结束，后文转入独立动作，没有必须立即衔接的回应。"
}
```

`offset`是绑定标准正文的字符坐标；`source_position`是原文的`[1基段号,0基段内字符位置]`。两者必须取当前文件的实际位置，示例不可照抄。切点左右不增删原文字词。脚本从通过的逐场报告中的`paragraph_map`及显式`fragments`重建逐字符对应，并核对切点，不使用近似锚点扩大范围；无法证明对应时回到现有来源映射处理，不虚构坐标放行。

## 保存与调用

```text
python <skill>/scripts/script_partition.py plan --project <project> --participants 3 --mode scene
python <skill>/scripts/script_partition.py plan --project <project> --participants 3 --mode balanced --boundaries <安全切点.json>
python <skill>/scripts/script_partition.py confirm --project <project> --proposal-hash <当前候选hash>
python <skill>/scripts/script_partition.py show --project <project>
python <skill>/scripts/script_partition.py resolve --project <project> --label A
```

每项目单独保存`script-partition.json`，协议`partition-v1`。前置记录保存为待定意图，不得写入正式`plan_id`；正式计划必须记录原文、标准稿、复核报告及绑定记录摘要，稳定`plan_id`、`version`、模式、人数、计数口径、候选切点和最终分段。每段有代号、原文坐标、精确标准正文`span`、字数与原文首尾摘录。分段代号按A…Z、AA、AB延续。相同候选重复运行或确认保持身份；已有分镜后不允许原位重拆重置分段身份，应保留旧计划或另建项目。来源、标准稿或复核报告变化使待定意图和旧计划失效，不改摘要冒充仍有效。

只读接口：`load_plan(project,state)`返回完整计划或`None`；文件损坏或来源失效时明确报错。`resolve_segment(project,state,label_or_span)`只接受已确认计划，按“A”/“A分段”或完全落在同一分段内的标准正文范围返回该段及计划身份；跨段范围返回`None`。调用方须继续保留实际重复覆盖检查，计划内尚未制作分段的顺序和间隔规则由分镜工作流统一处理。

分段代号是分工身份；分镜批次、分镜单元和节点名称遵循[文本母稿格式](storyboard-text-format.md)，不能仅因都是字母就混用。恢复时读取文件，不靠聊天中的首尾引句重新猜位置。

## 用户输出

按以下模板逐段输出，首尾各取实际原文1—2句话，保留原字词。分段很短时首尾摘录允许重合；仅展示重合不表示来源范围重叠。

```text
A分段：共n个字
开始：[本分段开始的1—2句话]
结束：[本分段结束的1—2句话]

B分段：共n个字
开始：[本分段开始的1—2句话]
结束：[本分段结束的1—2句话]
```

计划完成后立即请求本次分镜范围，可输入分段代号或开始、结束原句。已有明确范围时直接核对，不重复问；范围准确且历史检查已按对应工作流处理后进入分镜。
