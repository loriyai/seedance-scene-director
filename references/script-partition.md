# 剧本分工与范围映射

本模块负责标准化和资产交付后的原剧本正式分工计划，不改写原稿、标准剧本、场次、资产或已生成分镜。比例确认后的入口阶段只记录用户的分段意图或自定义范围，不在本模块生成正式分段。菜单顺序由[资产主流程](asset-workflow.md)维护，分镜入口与历史范围由[分镜工作流](storyboard-workflow.md)维护。

## 选择与人数

入口只有两种选择：

1. 按人数拆分
2. 用户自定义范围

比例确认后立即记录选择。选择1继续记录“请输入动画参与人数”的正整数；选择2记录用户提供的每个分段起止范围。记录阶段不解析标准剧本、不计算正式切点、不生成分段摘录，也不创建`script-partition.json`。人数为1时，正式计划生成完整一段。

以标准化阶段已保存的原文提取文本计数：所有非空白字符计入，含标点、原有标题及人物标签；空格、制表符和换行不计，工具新增段号和标准化新增文字不计。显示字数与均衡计算使用同一口径，不把该字数当作标准正文范围坐标。

## 按人数拆分

正式资产交付完成后，按入口记录的人数执行唯一的自动分工流程。先用总字数和人数计算理想目标切点：第`i`个切点的目标字数为`总字数×i/人数`，`i`从1到人数减1。目标字数只是定位依据，不要求任何分段严格达到均分。

在每个目标切点附近做局部事件连续性审查，向目标点前后寻找候选边界。审查范围随当前对白、动作和必要上下文扩展，直到能够判断边界是否安全；不对整个剧本预先建立事件单元表，也不把未来的正式分镜单元提前生成出来。

候选边界必须满足以下规则：

- 当前动作或信息已完成，下一内容可以独立开始；
- 不切断完整对白、完整动作或仍在进行的语义；
- 不切断必须连续的动作因果、接触、受力、回应、揭示或声音关系；
- 前后状态、方向、接触和结果可以承接；
- 同场且状态连续的内容不因换说话人、换镜头或字数目标而机械拆开。

候选边界须绑定当前原文、标准剧本和复核版本的精确映射，不能只凭近似引句定位。分工切点不得落在一条标准对白或动作记录内部；长对白或长动作造成的偏移可以使实际切点明显偏离目标字数，但不得为了靠近目标而硬切事件。

对所有目标切点的前后候选进行整体选择，保证切点按原文顺序递增、各段非空、完整覆盖原稿，并以目标偏差和段间差距的全局代价选择组合，不能逐个切点贪心决定。最终计划记录每个目标字数、实际字数、前后方向、偏移量和连续性理由。输出尽量均衡，但不承诺严格均分。

如果合法候选不足以形成要求数量的非空分段，说明具体缺少的目标切点或连续性约束，不能擅自减少人数、重复范围或切断事件。

该流程复用分镜规则中的自然语义、动作相位、信息识别和连续性判断；正式分镜阶段仍由分镜写作者决定4～30秒生成单元、镜头、摄影、声音和实际时长。事件连续性候选边界不是正式分镜单元边界，多个候选事件可以组合进一个分镜单元，单个较长事件也可在正式分镜阶段按实际语义气口跨单元安排。

## 局部切点审查数据

局部切点审查数据只登记各目标点附近的候选，不登记全剧本事件单元。需要生成当前项目和人数对应的模板时使用：

```text
python <skill>/scripts/script_partition.py boundary-template --project <project> --participants 3 --output <局部切点.json>
```

模板保留`policy`、`scope=target-local-v1`、`sources`、`participants`和`targets`。在`boundaries`中增加目标点附近的候选：

```json
{
  "target_index": 1,
  "offset": 180,
  "source_position": [12, 0],
  "side": "before",
  "distance": 6,
  "safe": true,
  "reason": "目标点落在一段未结束的对白中；前一段发言已完整结束，后文转入独立动作。"
}
```

`target_index`从1开始，`offset`是绑定标准正文的字符坐标，`source_position`是原文的`[1基段号,0基段内字符位置]`。`side`只能是`before`或`after`，并且必须与候选实际位于目标字数前后相符。`distance`是候选实际字数与目标字数的绝对偏差。`safe:true`表示已经完成该局部连续性判断，不能批量代签或用每条记录结束位置替代。

显式候选必须通过原文到标准剧本的精确映射、对白和动作完整性、目标方向、顺序、非空和覆盖检查。程序负责结构校验和全局择点；语义理由由负责当前剧本的写作者根据实际原文判断。

## 正式保存与调用

```text
python <skill>/scripts/script_partition.py plan --project <project> --participants 3 --boundaries <局部切点.json>
python <skill>/scripts/script_partition.py show --project <project>
python <skill>/scripts/script_partition.py resolve --project <project> --label A
```

每项目单独保存正式`script-partition.json`，协议`partition-v1`，正式计划的`mode`为`count`。计划只在标准化和资产交付完成后生成，记录原文、标准稿、复核报告及绑定记录摘要，稳定`plan_id`、`version`、人数、计数口径、目标字数、候选切点、全局选择依据和最终分段。每段有代号、原文坐标、精确标准正文`span`、字数与原文首尾摘录。分段代号按A…Z、AA、AB延续。相同候选重复运行保持身份；已有分镜后不允许原位重拆重置分段身份，应保留旧计划或另建项目。来源变化使旧计划失效，不改摘要冒充仍有效。

用户自定义范围不生成自动切点，但在正式分镜前保存为可追溯的范围基准：每段必须有唯一可定位的起止内容或标准正文坐标，所有范围按原顺序连续、非空、无重叠、无遗漏，并绑定当前原文和标准稿摘要。无法唯一定位或无法完成覆盖核对时停止并请求补充范围。

只读接口：`load_plan(project,state)`返回完整计划或`None`；文件损坏或来源失效时明确报错。`resolve_segment(project,state,label_or_span)`只接受已确认计划，按“A”/“A分段”或完全落在同一分段内的标准正文范围返回该段及计划身份；跨段范围返回`None`。调用方须继续保留实际重复覆盖检查，计划内尚未制作分段的顺序和间隔规则由分镜工作流统一处理。

分段代号是分工身份；分镜批次、分镜单元和节点名称遵循[文本母稿格式](storyboard-text-format.md)，不能仅因都是字母就混用。恢复时读取文件，不靠聊天中的首尾引句重新猜位置。

## 用户输出

按以下模板逐段输出，首尾各取实际原文1—2句话，保留原字词。分段很短时首尾摘录允许重合；仅展示重合不表示来源范围重叠。

```text
A分段：共n个字
开始：[本分段开始的1—2句话]
结束：[本分段结束的1—2句话]

B分段：共n个字
开始：[本分段开始的1—2句话]
结束：[本分段结束的1—2句话]
```

正式计划或用户自定义范围完成核对后，按[分镜工作流](storyboard-workflow.md)取得本次分镜范围。已记录且可唯一定位的范围直接复用，不重复询问；范围准确且历史检查已按对应工作流处理后进入分镜。
